# 需求问答

以下要求面向执行建站的 Agent；文中的「我」指正在请求建站的使用者。复用当前对话中已明确的回答、授权和完成状态。

参考常量基于 AIHOT 提交 `8d5a39bb47c917616798a3fdd71688a80f6c9b6c`；改代码前核对当前版本。来源见 [来源与许可](provenance.md)。

## 一、先问我什么：用问答补齐需求

我可能不懂技术。问题用普通话解释清楚，给少量可选项；不要让我先选数据库、向量数据库、任务队列或开发框架。技术上默认沿用 AIHOT。

先阅读当前对话和已有项目。已经有明确答案的项目直接复用，不要再问。每轮最多 5 个问题，一般不超过 3 轮；如果我一次给足信息，就跳过后续问答。可逆的实现细节由你决定。

### 第一轮：网站要帮助谁

请按下面的问题开始，已知项可以省略：

1. **你想做什么领域的网站，主要给谁看？** 例如「给独立开发者看的 AI 工具资讯」「给跨境卖家看的政策和平台变化」「给律师看的法规与案例」。
2. **读者看完之后，最希望获得什么帮助？** 例如快速了解大事、找到能直接使用的工具、发现机会、获得工作判断依据。请让我选一个主要用途，可以补充次要用途。
3. **你想给网站取什么名字？页面主要用什么语言？** 名字没想好时可以使用明确标注的临时名，最终品牌由我决定。
4. **你想要做出的网站还要包括什么？** 先说明默认已有精选、全部动态、热点事件、事件详情、主题、搜索、日报周报月报和管理后台，再问我要增删哪些。模型排行榜、邮件订阅、收藏同步、用户账户、会员付费、社群入口等都属于可选项，不要自动添加。
5. **外观希望接近 AIHOT 的信息布局，还是有自己的参考网站？** 我没有偏好时，沿用适合阅读资讯的简洁布局，适配手机和电脑，使用自己的站名、颜色和标志。

### 第二轮：收什么，选什么

根据第一轮回答追问：

1. **你希望盯哪些网站、公众号、X 账号、官方博客或其他来源？** 请我给名称或链接。如果我没有名单，先根据领域查找约 5–10 个候选，说明各自覆盖内容、接入方式、是否需要付费；让我选出首批来源，不把你猜测的名单直接当成我的长期信源。
2. **什么内容值得推荐，什么属于噪声？** 请我分别举 2–3 个例子。可以追问「重磅新闻和实用教程更看重哪个」「广告、融资、论文、活动通知要不要」。不要替我假定行业品味。
3. **栏目怎么分？** 先按我的行业提出约 4–8 个分类供我调整。分类应能覆盖首批素材且边界容易理解。公司、方向、内容形态可以另做主题标签，避免每个标签都变成一级栏目。
4. **你更希望少而准，还是尽量不漏？更新多频繁？** 如果我不知道，建议先用少量来源、小规模增量采集和每天一份日报验证，再根据漏选、误选情况调整。
5. **有哪些内容来源允许站内显示全文？是否需要翻译？** 默认显示摘要和原文链接；全文权限不明就不开放全文。外文摘要翻译与整篇全文翻译分别处理，后者另计调用量。

### 第三轮：运行条件与预算

1. **先在本地运行，还是准备部署到自己的服务器？** 已有域名和服务器时复用我已经提供的信息，先检查环境、空闲资源和端口。不知道时先完成本地可运行版本。
2. **是否已有大模型 API 和 Embedding API？使用哪家服务？** 只问提供商、模型名称和配置是否就绪；引导我在本地私有 `.env` 或宿主的密钥管理中填入凭据，不要求我在聊天中粘贴完整密钥。
3. **每月大致预算多少？初次真实试运行最多允许花多少？** 分清服务器、语言模型、Embedding、付费采集和其他服务。先明确小批量试运行额度，不将有 API Key 理解成无限消费授权。
4. **谁来管理网站？是否需要接收告警或推送？** 默认一个管理员；飞书、邮件、公众号和 X 等外发功能只接入我选定的目标，按我的授权启用。
5. **公开展示的作者介绍、联系方式、使用条款、隐私说明采用什么内容？** 可以先根据实际功能拟草稿供我修改；没有答案不妨碍本地开发，公开上线前落实需要确认的内容。

每轮允许我回答「你建议一个方案」「暂时没有」「先默认」。根据回答说明你的建议、采用的默认值及影响，不用同一个问题反复确认。行业主题、最终品牌、信源名单、价值标准和公开政策不能被你的猜测悄悄替代。

需求足够后，用一小段话总结「给谁看、收什么、怎么选、第一版包括什么、在哪里运行」。把决定保存在项目内一份简短的 `docs/project-brief.md`，之后直接开始已授权的开发。只有影响目标、成本或公开部署的关键缺口才等待我的回答；其它工作持续推进。
